## 执行语义

`run()` 先读取区间涉及的月度 MarketData 日期列，过滤、去重并排序，
然后遍历**每个实际交易日**。周末、节假日由真实数据决定。
按需向前读取日期列，寻找首日之前最多 `lookback - 1` 个交易日的预热历史；
到达数据集起点后使用已有历史，不补造数据。2016 年是当前数据起点，首日窗口只有一天。

三套完整数据默认每批读取 12 个自然月，使用一个标准库后台线程预取下一批。
播放缓存保留当前批次、所需历史尾部和最多一个待取批次，以及每只已出现股票的最近有效价格与日期。
模型历史窗口仍受 lookback 限制，参考价格状态不受该限制，不会缓存整个七年行情。
播放区间及模型预热期内，每个月的每套完整数据只读一次，日内接口使用已排序缓存切片。
日期列另有日历读取；必要时还会扫描更早 MarketData 的日期/代码/close 三列，初始化历史参考价。
这次扫描独立于 lookback，按月处理、只保留每只股票的最近有效记录，文件缺失直接报错。
`prefetch=False` 使用相同分批和切片逻辑，按需同步读取，供性能对照。
运行结束或发生异常时等待正在执行的读取结束，回收线程和缓存；再次 `run()` 重新读取。

模型每次收到三张独立副本，日期范围是截至当日、含当日在内的最多 `lookback` 个交易日。
Factor33 和研究行情按**每个历史日期的 Barra 成分**过滤，不把年度成分并集暴露给模型；
股票调入前不提供其非成分期历史，调出前的合法历史仍可出现在窗口中。
缓存可包含预取的未来日期，但传出的数据不包含未来行；模型修改输入不会影响缓存。

每日数据包统一包含开盘行情、收盘行情、可选研究窗口与当日组合输入；只有研究窗口交给用户模型。
`run()` 消费同一条数据流，每个交易日按以下顺序调用：

1. 公司行为、开盘市场状态、账户日初处理（预留每日 T+1 解锁）。
2. 调用 Accounting 的 `mark_at_open()`，仅传入开盘行情和历史参考价，为下单更新账户权益。
3. 若前一交易日生成了目标，调用 Broker 在本日开盘执行，随后清除待执行目标。
4. 每个交易日（含非调仓日和末日）调用 `mark_to_market()`，传入收盘行情，更新实际账户并收集持仓、净值审计行。
5. 调仓日收盘使用历史研究窗口调用 inference；Optimizer 接收当日 Barra 暴露及会计模块更新后的实际权重，目标排到下一交易日开盘。

这一区分对应需求文档的“目标权重到真实订单”“Portfolio Accounting”和“时间推进与数据隔离”：
模型接口不接收账户净值；Broker 所需权益、Optimizer 所需实际权重必须基于当时可见行情，
不能用事后估值或上次目标权重替代。开盘估值不能读取当日收盘信息，也不能覆盖日收益计算所需的上日收盘账户价值。
两个估值接口与 `current_weights()` 当前仍为占位，实现算法时须就地更新同一个实际账户，
区分真实价格模式与后复权收益模式。现阶段接通调用和数据交付，不产生有效的持仓市值或净值。

`DataProvider.playback()` 本身只交付数据，不调用金融模块；独立的 `valuation_inputs()` 提供区间行情，
供后续事后核对或批量分析使用，不能代替引擎内的逐日账户核算。最终绩效统计仍在循环结束后统一执行。

调仓日从区间内第一个交易日起每隔 `rebalance_interval` 个交易日选取。
末日没有区间内的下一交易日，因此只处理已有目标，不生成新的调仓目标。
单日区间仍交付开盘/收盘行情，运行日初处理及两个估值接口；无交易日时跳过循环，仍返回完整指标结构。

预测和交易结果先收集，循环结束后一次性合并为审计表，再进行事后 RankIC 评价、
指标计算和结果输出。未来收益标签只供评价器使用，不能进入模型和优化器。
金融模块仍为 `STUB`：尚不撮合、不计算金融指标、不写金融结果文件。
未来收益标签仍未实现，预测表的 `future_return` 为 `None`。
指标 `None` 表示未计算，不表示收益率为零。

依赖 pandas、pyarrow 和标准库线程池，不增加异步框架或机器学习依赖。
校验日期区间和正整数窗口/批次参数；信任源数据的列类型与唯一性，不逐行重复校验。
所需月份或列缺失、损坏文件和 inference 异常直接交给调用者，不静默跳过或重试。

框架默认不输出逐日跟踪信息，也不格式化调试日志。排查流程时可显式开启标准库日志：

```python
import logging
logging.basicConfig(level=logging.DEBUG, format="%(message)s")
```

开启调试输出或在用户 inference 中打印内容时，相应开销会计入运行耗时。

## 模块与后续顺序

| 设计模块 | 文件 | 待实现内容 |
|---|---|---|
| Submission Runner | `submission_runner.py` | 已直连句柄；模型由用户初始化 |
| Data Provider | `data_provider.py` | 已实现每日数据包、独立估值输入、历史参考价、成分过滤及 as-of；待补标签/交易数据 |
| Prediction Evaluator | `prediction_evaluator.py` | 标签、逐日 RankIC |
| Portfolio Optimizer | `portfolio_optimizer.py` | 排名变换、Top-K/tilt、约束优化 |
| Broker / Execution Engine | `broker.py` | T+1、整手/零股、涨跌停、先卖后买、实际账户 |
| Corporate Action Engine | `corporate_actions.py` | 真实价格模式公司行为，避免重复入账 |
| Cost Model | `cost_model.py` | 历史费率、佣金、印花税、过户费、滑点 |
| Portfolio Accounting | `accounting.py` | 引擎已接入开盘权益更新、每日收盘核算和实际权重接口；估值及 NAV/收益算法待实现 |
| Metrics | `metrics.py` | 预测和组合原始指标 |
| Result Writer | `result_writer.py` | JSON、CSV、运行日志 |

下一步实现仅供评价器使用的未来收益标签，再逐个补全预测评价、组合构建、
交易、会计、指标及文件输出。

## 验证与打包

完整测试包含 benchmark 内存采样测试，需安装对应的可选依赖。

```powershell
python -m pip install -e ".[benchmark]"
python -m unittest discover -s tests -v
uv build
```

也可先安装 `build`，再执行 `python -m build`，生成 wheel 和源码分发包。
测试使用 2016–2018 年的临时月度 Parquet，验证逐日顺序、下一开盘执行、区间边界、
审计汇总、跨批次预热、成分变化、同步/异步切片等价、可见性及副本隔离，
并通过线程事件验证读取与推理重叠、异常传播和资源清理。另验证跨年数据缺失、无效价格、
独立参考价初始化、估值 API 只读行情且不干扰播放、纯播放无金融调用和提前结束。
账户状态测试通过替身验证开盘权益在下单前更新、收盘权重传入优化器、每日审计行汇总，
以及会计异常停止决策并清理读取线程；这些测试验证调用契约，不代表金融算法已实现。
benchmark 测试验证不等间隔采样的峰值、时间加权平均值及失败时的采样线程清理。
